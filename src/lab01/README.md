# Лабораторная работа 1: Класс и инкапсуляция
## Вопрос 1. Что является сущностью?

**Ответ: Сервер (Server)**

В нашей предметной области реально существует объект **сервер** — это физический или виртуальный компьютер в IT-инфраструктуре, который:
- Имеет сетевое имя (hostname)
- Имеет IP-адрес
- Находится в определенном состоянии (активен, неактивен, обслуживание)
- К нему могут подключаться пользователи
- Имеет ограничение на количество подключений

Это не абстракция, а реально существующий объект в IT-инфраструктуре.

---

## Вопрос 2. Какие у него атрибуты?

### Атрибуты-характеристики (данные):
| Атрибут | Тип | Описание |
|---------|-----|----------|
| `hostname` | строка | Имя сервера (например, "web-01") |
| `ip_address` | строка | IP-адрес в формате IPv4 |
| `status` | строка | Текущее состояние: "active", "inactive", "maintenance" |
| `max_connections` | число | Максимальное количество одновременных подключений |
| `current_connections` | число | Текущее количество подключений |
| `created_at` | дата/время | Когда сервер был создан |
| `users` | список | Кто сейчас подключен |

### Атрибуты-действия (методы):
| Метод | Описание |
|-------|----------|
| `connect_user(username)` | Подключить пользователя |
| `disconnect_user(username)` | Отключить пользователя |
| `activate()` | Активировать сервер |
| `deactivate()` | Деактивировать сервер |
| `maintenance_mode()` | Перевести в режим обслуживания |

## Вопрос 3. Какие инварианты?

**Инварианты класса Server** (правила, которые всегда должны соблюдаться):

### Инварианты для hostname:
- `hostname` не может быть пустой строкой
- `hostname` может содержать только буквы, цифры и дефис
- Длина `hostname` ≤ 63 символов

### Инварианты для ip_address:
- IP-адрес должен соответствовать формату IPv4 (4 октета, разделенные точками)
- Каждый октет должен быть в диапазоне 0-255

### Инварианты для status:
- `status` может быть только одним из: `"active"`, `"inactive"`, `"maintenance"`

### Инварианты для подключений:
- `current_connections` всегда ≥ 0
- `current_connections` всегда ≤ `max_connections`

### Инварианты для max_connections:
- `max_connections` всегда > 0
- `max_connections` ≤ 1000 (разумное ограничение)

### Бизнес-инварианты (логические правила):
- Если сервер в статусе `"maintenance"`, то `current_connections` должно быть 0
- Если сервер в статусе `"inactive"`, то `current_connections` должно быть 0

## Вопрос 4. Что значит “равенство”?

**Два сервера считаются равными, если совпадает их IP-адрес.**

## Вопрос 5. Есть ли состояние?

**Да, у сервера есть три состояния:**

### Состояния:
1. **`"active"` (активен)** — сервер работает, можно подключаться
2. **`"inactive"` (неактивен)** — сервер выключен/недоступен, подключения невозможны
3. **`"maintenance"` (обслуживание)** — сервер на техническом обслуживании, подключения невозможны

## Описание класса Server
### Атрибут класса

Класс содержит один **атрибут класса** – `os_type` (тип операционной системы). Данный атрибут является общим для всех экземпляров класса и демонстрирует разницу между атрибутами класса и экземпляра. По умолчанию установлено значение "Linux", что соответствует типичной серверной операционной системе.

### Конструктор

Конструктор `__init__` принимает следующие параметры:
- `hostname` (обязательный) – имя сервера
- `ip_address` (обязательный) – IP-адрес сервера
- `max_connections` (необязательный, по умолчанию 100) – лимит подключений
- `status` (необязательный, по умолчанию "inactive") – начальный статус

При создании объекта:
1. Все переданные параметры проходят валидацию с помощью функций из модуля `validate.py`
2. Инициализируются закрытые атрибуты
3. Устанавливаются значения по умолчанию (`current_connections = 0`, `created_at = текущее время`)
4. Создается пустой список для хранения подключенных пользователей

Если какой-либо параметр не проходит валидацию, конструктор выбрасывает соответствующее исключение, что предотвращает создание объекта в некорректном состоянии.

### Свойства (`@property`)

Для контролируемого доступа к закрытым атрибутам используются свойства, которые позволяют выполнять дополнительную логику при чтении и изменении значений.

#### Свойства только для чтения (геттеры)

| Свойство | Доступ | Описание |
|----------|--------|----------|
| `hostname` | Только чтение | Возвращает имя сервера |
| `ip_address` | Только чтение | Возвращает IP-адрес сервера |
| `current_connections` | Только чтение | Возвращает текущее количество подключений |
| `created_at` | Только чтение | Возвращает дату создания сервера |
py
#### Свойства с возможностью изменения (сеттеры)

**Свойство `status`:**
- Геттер возвращает текущий статус
- Сеттер принимает новое значение, проверяет его допустимость через функцию валидации
- Реализует бизнес-логику: запрещает перевод из "active" в "maintenance" при наличии активных подключений
- Выводит информационное сообщение об изменении статуса

**Свойство `max_connections`:**
- Геттер возвращает текущий лимит подключений
- Сеттер проверяет, что новое значение является положительным целым числом и не превышает 1000
- Реализует бизнес-логику: запрещает уменьшение лимита ниже текущего количества подключений
- Выводит информационное сообщение об изменении лимита
