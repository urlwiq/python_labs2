# Лабораторная работа 1: Класс и инкапсуляция
## Цель работы

Освоить основные принципы объектно-ориентированного программирования в Python:
- Создание пользовательских классов
- Инкапсуляция данных (закрытые атрибуты)
- Использование свойств (`@property`) для контролируемого доступа
- Переопределение магических методов (`__str__`, `__repr__`, `__eq__`)
- Разделение ответственности между модулями
- Реализация бизнес-логики и проверка состояний объекта

## Предметная область

В рамках лабораторной работы был реализован класс `Server`, моделирующий работу сервера в IT-инфраструктуре. 
Класс отражает следующие сущности:
- **Server** – основной класс, представляющий сервер
- **User** – пользователи, подключающиеся к серверу
- **Session** – сессии подключений
- **Repository** – репозитории, размещенные на сервере
- **Issue** – возможные проблемы и состояния сервера

## Описание класса Server
### Атрибут класса

Класс содержит один **атрибут класса** – `os_type` (тип операционной системы). Данный атрибут является общим для всех экземпляров класса и демонстрирует разницу между атрибутами класса и экземпляра. По умолчанию установлено значение "Linux", что соответствует типичной серверной операционной системе.

### Конструктор

Конструктор `__init__` принимает следующие параметры:
- `hostname` (обязательный) – имя сервера
- `ip_address` (обязательный) – IP-адрес сервера
- `max_connections` (необязательный, по умолчанию 100) – лимит подключений
- `status` (необязательный, по умолчанию "inactive") – начальный статус

При создании объекта:
1. Все переданные параметры проходят валидацию с помощью функций из модуля `validate.py`
2. Инициализируются закрытые атрибуты
3. Устанавливаются значения по умолчанию (`current_connections = 0`, `created_at = текущее время`)
4. Создается пустой список для хранения подключенных пользователей

Если какой-либо параметр не проходит валидацию, конструктор выбрасывает соответствующее исключение, что предотвращает создание объекта в некорректном состоянии.

### Свойства (`@property`)

Для контролируемого доступа к закрытым атрибутам используются свойства, которые позволяют выполнять дополнительную логику при чтении и изменении значений.

#### Свойства только для чтения (геттеры)

| Свойство | Доступ | Описание |
|----------|--------|----------|
| `hostname` | Только чтение | Возвращает имя сервера |
| `ip_address` | Только чтение | Возвращает IP-адрес сервера |
| `current_connections` | Только чтение | Возвращает текущее количество подключений |
| `created_at` | Только чтение | Возвращает дату создания сервера |

#### Свойства с возможностью изменения (сеттеры)

**Свойство `status`:**
- Геттер возвращает текущий статус
- Сеттер принимает новое значение, проверяет его допустимость через функцию валидации
- Реализует бизнес-логику: запрещает перевод из "active" в "maintenance" при наличии активных подключений
- Выводит информационное сообщение об изменении статуса

**Свойство `max_connections`:**
- Геттер возвращает текущий лимит подключений
- Сеттер проверяет, что новое значение является положительным целым числом и не превышает 1000
- Реализует бизнес-логику: запрещает уменьшение лимита ниже текущего количества подключений
- Выводит информационное сообщение об изменении лимита
