# Лабораторная работа №6 - Generics и typing

## 1. Цель работы

Освоить систему аннотаций типов в Python (typing), научиться создавать обобщённые (generic) классы с помощью TypeVar и Generic, понять концепцию структурной типизации через typing.Protocol.

## 2. Описание реализованных типов и контейнеров

### Generic-коллекция `TypedCollection[T]`

Обобщённая версия коллекции из ЛР-2. Хранит элементы только одного типа T.

| Метод | Аннотация | Описание |
|-------|-----------|----------|
| `add(item: T) -> None` | Добавить элемент |
| `remove(item: T) -> None` | Удалить элемент |
| `get_all() -> list[T]` | Получить все элементы |
| `__len__() -> int` | Количество элементов |
| `__iter__()` | Итератор |
| `__getitem__(index: int) -> T` | Доступ по индексу |
| `find(predicate: Callable[[T], bool]) -> Optional[T]` | Поиск элемента |
| `filter(predicate: Callable[[T], bool]) -> list[T]` | Фильтрация |
| `map(transform: Callable[[T], R]) -> list[R]` | Преобразование |

### TypeVar

| TypeVar | Назначение |
|---------|------------|
| `T` | Тип элементов в коллекции |
| `R` | Тип результата после map (может отличаться от T) |
| `D` | Тип с ограничением bound=Displayable |
| `S` | Тип с ограничением bound=Scorable |

### Protocol

| Протокол | Метод | Описание |
|----------|-------|----------|
| `Displayable` | `display() -> str` | Объект можно отобразить |
| `Scorable` | `score() -> float` | Объект можно оценить |

Классы из ЛР-3 (Server, WebServer, DatabaseServer, FileServer) **НЕ наследуются** от этих протоколов, но имеют соответствующие методы, поэтому подходят под них (структурная типизация).

### Сценарий 2: find, filter, map (на 4)

**Что демонстрирует:** работу методов `find()`, `filter()`, `map()` с разными функциями.

**Как работает:** 
- `find()` — поиск существующего и несуществующего элемента
- `filter()` — отбор активных серверов и веб-серверов
- `map()` — преобразование в список строк (имена) и в список чисел (нагрузка)

Показывается, что тип результата map меняется: `list[str]` и `list[float]`.

### Сценарий 3: Protocol и bound (на 5)

**Что демонстрирует:** использование `TypedCollection` с ограничением по протоколу `Displayable` и `Scorable`.

**Как работает:** 
- Создаётся `TypedCollection[D]` с ограничением `Displayable`
- Добавляются объекты разных типов (WebServer, DatabaseServer, FileServer)
- Объекты не наследуют протокол явно, но имеют метод `display()` — подходят
- Вызывается `display()` для каждого объекта (безопасно, так как протокол гарантирует наличие метода)

Аналогично для `TypedCollection[S]` с протоколом `Scorable`.

## 4. Вывод

В ходе лабораторной работы было изучено:

- **Аннотации типов** — параметры, возвращаемые значения, атрибуты
- **Generic** — `TypeVar` и `Generic` для создания обобщённых классов
- **TypedCollection** — контейнер, хранящий элементы одного типа
- **find, filter, map** — методы с корректными аннотациями типов
- **Protocol** — структурная типизация (объект подходит, если имеет нужные методы, без явного наследования)
- **Bound** — ограничение TypeVar протоколом
