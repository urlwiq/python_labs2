# Лабораторная работа №6 - Generics и typing

## 1. Цель работы

Освоить систему аннотаций типов в Python (typing), научиться создавать обобщённые (generic) классы с помощью TypeVar и Generic, понять концепцию структурной типизации через typing.Protocol.

## 2. Описание реализованных типов и контейнеров

### Generic-коллекция `TypedCollection[T]`

Обобщённая версия коллекции из ЛР-2. Хранит элементы только одного типа T.

**Методы:**

- **`add(item: T) -> None`** — Добавить элемент в коллекцию.
- **`remove(item: T) -> None`** — Удалить элемент из коллекции.
- **`get_all() -> list[T]`** — Получить список всех элементов.
- **`__len__() -> int`** — Вернуть количество элементов. Позволяет использовать `len()`.
- **`__iter__()`** — Вернуть итератор. Позволяет использовать `for item in collection`.
- **`__getitem__(index: int) -> T`** — Доступ по индексу. Позволяет писать `collection[0]`.
- **`find(predicate: Callable[[T], bool]) -> Optional[T]`** — Найти первый элемент, удовлетворяющий условию. Возвращает элемент или `None`.
- **`filter(predicate: Callable[[T], bool]) -> list[T]`** — Вернуть список всех элементов, удовлетворяющих условию.
- **`map(transform: Callable[[T], R]) -> list[R]`** — Применить функцию преобразования к каждому элементу. Возвращает список результатов, тип которых может отличаться от исходного (например, `TypedCollection[Server]` → `list[str]`).

### TypeVar

- **`T`** — Тип элементов в коллекции. Используется для создания Generic-класса.
- **`R`** — Тип результата после `map()`. Может отличаться от `T`.
- **`D`** — Тип с ограничением `bound=Displayable`. Используется для коллекций, которые могут содержать только объекты с методом `display()`.
- **`S`** — Тип с ограничением `bound=Scorable`. Используется для коллекций, которые могут содержать только объекты с методом `score()`.

### Protocol (структурная типизация)

**`Displayable`** — протокол, требующий наличия метода `display() -> str`. Любой класс, у которого есть этот метод, автоматически соответствует протоколу, даже без явного наследования.

**`Scorable`** — протокол, требующий наличия метода `score() -> float`.

Классы из ЛР-3 (`Server`, `WebServer`, `DatabaseServer`, `FileServer`) не наследуются от этих протоколов, но имеют соответствующие методы (добавлены через `add_protocol_methods()`), поэтому подходят под них. Это и есть структурная типизация — объект подходит, если делает то, что нужно, а не потому что он наследник.

### Сценарий 2: find, filter, map

**Что демонстрирует:** работу методов `find()`, `filter()`, `map()` с разными функциями.

**Как работает:** 
- `find()` — поиск существующего и несуществующего элемента
- `filter()` — отбор активных серверов и веб-серверов
- `map()` — преобразование в список строк (имена) и в список чисел (нагрузка)

Показывается, что тип результата map меняется: `list[str]` и `list[float]`.

### Сценарий 3: Protocol и bound

**Что демонстрирует:** использование `TypedCollection` с ограничением по протоколу `Displayable` и `Scorable`.

**Как работает:** 
- Создаётся `TypedCollection[D]` с ограничением `Displayable`
- Добавляются объекты разных типов (WebServer, DatabaseServer, FileServer)
- Объекты не наследуют протокол явно, но имеют метод `display()` — подходят
- Вызывается `display()` для каждого объекта (безопасно, так как протокол гарантирует наличие метода)

Аналогично для `TypedCollection[S]` с протоколом `Scorable`.
