# Лабораторная работа №3 - Наследование и иерархия классов

## Классы

### Базовый класс Server
Базовый класс для всех типов серверов. Содержит общие атрибуты: hostname, ip_address, max_connections, status, current_connections.

### Производные классы

| Класс | Описание | Новые атрибуты | Новые методы |
|-------|----------|----------------|--------------|
| WebServer | Веб-сервер | domain, ssl_enabled | handle_request(), get_http_status() |
| DatabaseServer | Сервер БД | db_type, storage_gb | execute_query(), get_free_space() |
| FileServer | Файловый сервер | protocol, files | upload_file(), get_avg_file_size() |

### Полиморфные методы
- `get_server_type()` - возвращает тип сервера
- `calculate_load()` - рассчитывает нагрузку (переопределён в каждом классе)

## Коллекция ServerCollection (из ЛР-2)

### Реализованные методы

| Метод | Описание |
|-------|----------|
| add(server) | Добавить сервер |
| remove(server) | Удалить сервер |
| get_all() | Получить все серверы |
| find_by_name(hostname) | Поиск по имени |
| find_by_ip(ip) | Поиск по IP |
| find_by_status(status) | Поиск по статусу |
| remove_at(index) | Удаление по индексу |
| sort_by_hostname() | Сортировка по имени |
| get_active_servers() | Получить активные серверы |

### Магические методы
- `__len__()` - длина коллекции
- `__iter__()` - итерация в цикле for
- `__getitem__()` - доступ по индексу

## Сценарий 1: Базовое наследование

**Что демонстрирует:** создание объектов разных типов (WebServer, DatabaseServer, FileServer), использование новых методов дочерних классов, переопределение метода `__str__`.

**Как работает:** Создаются объекты WebServer, DatabaseServer и FileServer. Для веб-сервера вызывается метод `handle_request()` дважды, выводится HTTP статус. Для сервера БД выполняются SQL-запросы методом `execute_query()`, выводится свободное место. Для файлового сервера загружаются файлы методом `upload_file()`, вычисляется средний размер. В конце выводятся все объекты через переопределённый `__str__`, который показывает домен, тип БД, протокол и нагрузку.

## Сценарий 2: Полиморфизм

**Что демонстрирует:** работу полиморфизма (один метод — разное поведение), проверку типов через `isinstance()`, интеграцию с коллекцией из ЛР-2.

**Как работает:** Создаётся коллекция ServerCollection, в которую добавляются три разных сервера (WebServer, DatabaseServer, FileServer). Демонстрируется полиморфизм через метод `get_server_type()`: для каждого сервера возвращается свой тип. Затем через `calculate_load()` показывается разная логика расчёта нагрузки для разных типов серверов. С помощью `isinstance()` проверяются типы объектов и выводятся их специфичные атрибуты (SSL, тип БД, протокол). Коллекция успешно хранит и обрабатывает все типы серверов.

## Сценарий 3: Фильтрация по типу и полиморфизм без условий

**Что демонстрирует:** фильтрацию объектов по типу, полиморфизм без использования условных операторов (Good паттерн), статистику по типам серверов.

**Как работает:** Создаётся коллекция из 7 серверов разных типов (2 веб-сервера, 2 сервера БД, 2 файловых сервера и 1 обычный сервер). Демонстрируется фильтрация: выбираются только веб-серверы, только серверы БД и только файловые серверы с помощью `isinstance()`. Показывается разница между анти-паттерном (`if type(server) == WebServer`) и Good-паттерном (`server.get_server_type()`). В конце выводится статистика по типам серверов в коллекции.

## Вывод

В ходе лабораторной работы было изучено:

- **Наследование** - создание дочерних классов `WebServer`, `DatabaseServer`, `FileServer` от базового класса `Server`
- **super()** - вызов конструктора родительского класса
- **Переопределение методов** - изменение поведения `__str__` и `calculate_load()` в каждом дочернем классе
- **Полиморфизм** - один метод `get_server_type()` даёт разные результаты в разных классах
- **isinstance()** - проверка типа объектов для фильтрации
- **Интеграция с коллекцией** - коллекция из ЛР-2 успешно хранит и обрабатывает объекты всех дочерних классов
- **Полиморфизм без условий** - использование общего интерфейса вместо проверки типов (Good паттерн)
